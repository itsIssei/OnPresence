# Development

## Stack

- **Backend:** Go (module `onpresence`), standard library `net/http` with method routing, `modernc.org/sqlite` (pure Go, WAL mode), `log/slog`. There is no CGO, so it cross-compiles anywhere.
- **Frontend:** Vite, TypeScript, React 19, Tailwind v4, shadcn/ui (`web/`). The **public page** is built with **Preact** through `preact/compat` (about 60 KB gzip). The **dashboard** uses React. Both builds share the same source.
- The built frontend (`web/dist`) is embedded in the binary (`embed.go`).

## Layout

```
embed.go              embeds web/dist
server/main.go        config, store, housekeeping (session purge, daily backup), HTTP server
server/config/        environment variables
server/models/        JSON/DB shapes. Settings = every card option (one JSON column). validate.go
server/store/         SQLite: migrate.go (versioned), seed, auth + sessions, totp, profile + snapshots, collections, content (export/import), uploads + backups
server/api/           routes (api.go), middleware (CSP, CSRF, auth, logging), handlers, uploads, og.go (link preview image), static.go (SPA + SEO meta)
server/services/      outbound calls: lanyard, steam, lastfm, anilist, gamesearch, musicfetch. httpclient.go = public-IP-only clients
server/totp/          RFC 6238 one-time codes (standard library only)
tools/brandgen/       renders the PNG icons and favicon from the logo shapes
tools/originals/       renders the built-in animated decorations and effects (APNG)
tools/brand/          builds docs/brand (banner, social preview, wordmarks)
tools/demo/           builds the demo persona (docs/demo + web/public/img/demo)
tools/screenshots/    takes the README screenshots with headless Chrome/Edge
web/src/card/         ProfileCard, Avatar (+decoration), ProfileEffect, Activity, BackgroundFX. Shared by the site and the dashboard preview.
web/src/vault/        display case (lazy loaded)
web/src/site/         public page entry (index.html)
web/src/admin/        dashboard entry (admin.html): draft.tsx (profile draft + save bar), Collection.tsx (sortable CRUD), kit.tsx, pages/
web/src/lib/          API client, types (mirror models.go), catalog, presence, theme, icons, strings
web/public/           brand icons, verdict badges, built-in decorations/effects (img/, data/)
deploy/               Caddy, Traefik and systemd examples
```

## Run locally

```bash
cd web && npm ci && npm run build && cd ..   # the server embeds web/dist
DEV=1 DATA_DIR=./data-dev go run ./server     # prints the setup code
cd web && npm run dev                         # http://localhost:5173 with hot reload; proxies the API to :8080
```

Checks (CI runs the same):

```bash
go vet ./... && go test ./...
cd web && npm run lint && npx tsc -b
```

## Conventions

- API routes live under `/api/v1/...`. Admin routes wrap their handler with `s.admin(...)`. Validate every field (helpers in `admin.go`). URLs must pass `models.IsSafeURL` (https, `/uploads/` or `/img/`).
- **New card option:** add it to `models.Settings` with a default and a `Normalize` rule, to `web/src/lib/types.ts`, to the card component, and as a dashboard control. No migration needed.
- **New table or column:** add a migration to `server/store/migrate.go`. Never edit a released migration.
- Send errors to clients through `writeError` / `serverError`. Never return raw `err.Error()` from upstream calls.
- Frontend: no `innerHTML` or `dangerouslySetInnerHTML`. Keep `web/src/card` free of dashboard-only dependencies so the public bundle stays small.
- `web/src/components/ui` and `web/src/hooks` are generated by shadcn. Edit them sparingly.
- Keep avatar decorations and profile effects working on both the card and the preview. They are the core feature.
- Commits follow Conventional Commits. Line endings are LF.

## Releasing

Push a tag like `v1.2.0`. `.github/workflows/release.yml` publishes the multi-arch image to `ghcr.io/<owner>/onpresence` and attaches binaries to the GitHub release. The first time, make the package public under GitHub → Packages → onpresence → Package settings.

## README screenshots

```bash
python tools/demo/build.py                       # only when the demo content changes
DEV=1 DATA_DIR=./data-shots ADMIN_PASSWORD=screenshots-only go run ./server
# in another terminal: load docs/demo/demo-content.json (Dashboard → Restore from JSON), then
BASE=http://localhost:8080 ADMIN_PASSWORD=screenshots-only node tools/screenshots/shoot.mjs
```

## Brand assets

`docs/brand/` holds the banner, the social preview (upload `social-preview.png` under GitHub → Settings → Social preview) and wordmarks for dark and light backgrounds. Rebuild them with `python tools/brand/build.py` (needs `pip install fonttools brotli`).

## Rebranding the icons

The icons live in `web/public/img/brand/`. After you change the colors in `icon.svg`, regenerate the PNGs and favicon with the same colors:

```bash
go run ./tools/brandgen -bg "#110b1f" -from "#c4b5fd" -to "#7c3aed" -dot "#22c55e"
```
